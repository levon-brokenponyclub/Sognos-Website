# Refine — Full Instructions

## Purpose
Full front-end polish on an already-Passed page. This is where the paint goes on.

## What Refine covers
- Final imagery and asset placement
- Framer Motion animation — entrance, scroll, interaction
- Colour application — full Sognos palette, deliberate use of accent/tint/navy
- Typography fine-tuning within the token system
- Hover states, micro-interactions, responsive polish
- Accessibility — focus states, aria labels, motion-safe variants

## What Refine does NOT do
- Re-litigate token decisions from Pass — those are settled
- Change copy or add new sections
- Introduce new components not in `docs/COMPONENT_INVENTORY.md` without
  flagging first

## Step 0 — Read first
- `docs/ROLLOUT_PROCESS.md` — confirm Pass is marked complete for this page
- `docs/COMPONENT_INVENTORY.md` — any reusable animation patterns

## Process
Refine is more open-ended than Scaffold or Pass. Work section by section,
share output, discuss, iterate. When a section feels done, move to the next.

## When Refine is done
Update `docs/CHANGELOG.md`, `docs/PROJECT_STATE.md`, and the status table.
Notify the user. Do not run a build.
